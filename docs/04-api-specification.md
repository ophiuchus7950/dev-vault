# DevVault — API Specification

- **Status:** Draft v1.0
- **Last updated:** 2026-11-04
- **Base URL:** `/api/v1`
- **Content type:** `application/json; charset=utf-8`
- **Machine-readable contract:** OpenAPI 3.1 generated by [utoipa](https://github.com/juhaku/utoipa), served at `GET /api-docs/openapi.json`; Swagger UI at `GET /docs`.
- **Related:** [Architecture §6](../01-architecture.md#6-api-layer) · [DB Schema](./03-database-schema.md) · [ADR-0004](../adr/0004-cursor-pagination.md)

> This document is the human-readable companion to the generated OpenAPI spec. When they disagree, the generated spec wins — and that's a bug to fix.

## 1. Conventions

| Aspect | Rule |
| ------ | ---- |
| Base path | `/api/v1` (versioning; breaking changes → `/api/v2`) |
| Casing | JSON fields are `snake_case` |
| Timestamps | RFC3339 UTC strings, e.g. `2026-11-04T15:04:05Z` |
| IDs | UUIDv7 strings |
| Create | `201 Created` + `Location: /api/v1/entries/{id}` |
| Delete | `204 No Content` (no body) |
| Update | `PATCH`, partial semantics; `ETag` + `If-Match` required |
| Missing row | `404` |
| Validation | `422` with field-level details |
| Stale update | `409` |
| Rate limiting | Not applied (single-user, local) |

### Common request headers

| Header | Used on | Purpose |
| ------ | ------- | ------- |
| `Content-Type: application/json` | POST/PATCH | Required for bodies |
| `If-Match: "<etag>"` | PATCH/DELETE | Optimistic concurrency |
| `Accept: application/json` | all | Default |

### Common response headers

| Header | Used on | Meaning |
| ------ | ------- | ------- |
| `ETag: "<hash>"` | GET one, PATCH | Version token for the row |
| `Location: /api/v1/entries/{id}` | POST | URI of the created resource |
| `X-Request-Id` | all | Correlation id (echoes or generates) |

## 2. Error model

All errors share one envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      { "field": "title", "code": "length", "message": "title must be 1..300 characters" }
    ]
  }
}
```

| `code` | HTTP | When |
| ------ | ---- | ---- |
| `VALIDATION_ERROR` | 422 | DTO failed `validator` rules |
| `NOT_FOUND` | 404 | Resource id/slug does not exist (or is purged) |
| `CONFLICT` | 409 | `If-Match` mismatch; duplicate slug; tag name collision |
| `INVALID_CURSOR` | 422 | Malformed/expired pagination cursor |
| `UNSUPPORTED_FORMAT` | 422 | Bad `?format=` value |
| `PAYLOAD_TOO_LARGE` | 413 | Import body exceeds limit |
| `INTERNAL_ERROR` | 500 | Unexpected; details only in server logs (`X-Request-Id`) |

## 3. Data shapes

### `Entry` (response)

```json
{
  "id": "0192f3c4-1a2b-7c3d-8e9f-0a1b2c3d4e5f",
  "kind": "snippet",
  "title": "Postgres upsert with ON CONFLICT",
  "body": "INSERT INTO tags (id, name) VALUES ($1, $2)\nON CONFLICT (lower(name)) DO UPDATE SET name = tags.name;",
  "language": "sql",
  "shell": null,
  "url": null,
  "tags": ["postgres", "sql"],
  "collections": ["backend"],
  "is_pinned": true,
  "is_archived": false,
  "created_at": "2026-11-04T15:04:05Z",
  "updated_at": "2026-11-04T15:30:00Z",
  "deleted_at": null
}
```

### `CreateEntryRequest` / `UpdateEntryRequest`

```json
{
  "kind": "snippet",
  "title": "Postgres upsert with ON CONFLICT",
  "body": "INSERT INTO ...",
  "language": "sql",
  "tags": ["postgres", "sql"],
  "collections": ["backend"],
  "is_pinned": false,
  "is_archived": false
}
```

| Field | Type | Create | Notes |
| ----- | ---- | ------ | ----- |
| `kind` | enum | required | `snippet\|command\|note\|link\|doc` |
| `title` | string | required | 1..300 chars |
| `body` | string | optional | default `""` |
| `language` | string? | optional | snippets; ≤ 50 chars |
| `shell` | string? | optional | commands; ≤ 50 chars |
| `url` | string? | optional | links; **required when `kind=link`**; ≤ 2048 chars |
| `tags` | string[] | optional | names; upserted, case-insensitive |
| `collections` | string[] | optional | slugs or UUIDs; must exist |
| `is_pinned` | bool | optional | default `false` |
| `is_archived` | bool | optional | default `false` |

`UpdateEntryRequest` is the same but every field optional (partial PATCH). Sending `kind` on update is allowed only if the row isn't referenced in ways that would break invariants (currently always allowed).

## 4. Endpoints

### 4.1 Health

#### `GET /health`
Liveness. Always `200` if the process is up.

```json
{ "status": "ok", "version": "1.0.0", "uptime_s": 42 }
```

#### `GET /ready`
Readiness: checks DB connectivity + applied migration version. `200` when ready, `503` otherwise.

```json
{ "status": "ready", "db": "ok", "migration": "0006_create_indexes" }
```

---

### 4.2 Entries

#### `GET /api/v1/entries`

List live entries with filtering, sorting and cursor pagination.

**Query parameters**

| Param | Type | Default | Notes |
| ----- | ---- | ------- | ----- |
| `kind` | enum | — | filter by kind |
| `language` | string | — | exact match |
| `tag` | string | — | repeatable; **AND** semantics (entry must have all) |
| `collection` | string | — | slug or UUID |
| `is_pinned` | bool | — | filter |
| `is_archived` | bool | — | default excludes archived unless set |
| `q` | string | — | optional quick-FTS filter (prefer `/search` for full behaviour) |
| `sort` | enum | `updated_at` | `updated_at\|created_at\|title\|relevance` |
| `order` | enum | `desc` | `asc\|desc` |
| `limit` | int | 20 | 1..100 (`MAX_PAGE_SIZE`) |
| `cursor` | string | — | opaque; from a previous `next_cursor` |

**Request**
```http
GET /api/v1/entries?kind=snippet&tag=postgres&tag=sql&sort=created_at&order=desc&limit=20
```

**Response `200`**
```json
{
  "data": [ { /* Entry */ } ],
  "next_cursor": "eyJjcmVhdGVkX2F0Ijoi...",
  "has_more": true
}
```

- `next_cursor` is `null` on the last page. Pass it back to fetch the next page.

---

#### `POST /api/v1/entries`

Create an entry. Upserts tags; validates collections exist.

**Request**
```http
POST /api/v1/entries
Content-Type: application/json

{ "kind": "snippet", "title": "…", "body": "…", "language": "sql", "tags": ["postgres"] }
```

**Responses**
- `201 Created` — `Location: /api/v1/entries/{id}`, `ETag` header, body = `Entry`.
- `422 VALIDATION_ERROR` — e.g. `kind=link` without `url`, title too long.
- `409 CONFLICT` — a referenced collection doesn't exist (or, if `create_missing=false`, unknown collection).

---

#### `GET /api/v1/entries/{id}`

**Response `200`** — `Entry`, with `ETag: "<hash>"`.
**`404 NOT_FOUND`** — unknown or purged id.

---

#### `PATCH /api/v1/entries/{id}`

Partial update. **Requires `If-Match`** with the current `ETag`.

**Request**
```http
PATCH /api/v1/entries/{id}
If-Match: "a1b2c3"
Content-Type: application/json

{ "title": "Renamed", "tags": ["postgres", "upsert"] }
```

**Responses**
- `200 OK` — updated `Entry` + new `ETag`.
- `409 CONFLICT` — `If-Match` stale (someone/something edited it) → re-fetch and retry.
- `412 Precondition Required`-style behaviour is expressed as `428` if `If-Match` is omitted — **policy:** `428 Precondition Required`.
- `422 VALIDATION_ERROR`.

> `tags`/`collections` arrays are **replace-set** semantics: the provided list becomes the entry's full set. Omit them to leave unchanged.

---

#### `DELETE /api/v1/entries/{id}`

Soft delete (moves to Trash).

- `204 No Content`
- `404 NOT_FOUND` if unknown or already trashed.

#### `POST /api/v1/entries/{id}/restore`
Restore from Trash. `200 OK` + `Entry`.
- `409 CONFLICT` if the entry is not in Trash.

#### `DELETE /api/v1/entries/{id}/purge`
Permanently delete. Only allowed for Trash entries.
- `204 No Content` · `409` if not trashed · `404` if unknown.

#### `GET /api/v1/trash`
Same shape/pagination as `GET /entries`, but lists **only** soft-deleted rows (ordered by `deleted_at DESC`).

---

### 4.3 Tags

#### `GET /api/v1/tags`
List tags with live-entry counts.

```json
{ "data": [ { "id": "…", "name": "postgres", "count": 12 } ] }
```

Query: `?sort=name|count&order=asc|desc&q=<prefix>` for autocomplete.

#### `PATCH /api/v1/tags/{id}`
Rename a tag (case-insensitive unique).

```json
{ "name": "postgresql" }
```
- `200 OK` · `409 CONFLICT` if the new name collides.

#### `DELETE /api/v1/tags/{id}`
Delete a tag; cascades removal from `entry_tags`. `204 No Content`.

> Attaching/detaching tags is done via the entry's `tags` array on create/PATCH. There is no separate attach endpoint in v1.

---

### 4.4 Collections

#### `GET /api/v1/collections`
```json
{ "data": [ { "id": "…", "name": "Backend", "slug": "backend", "description": "", "entry_count": 23 } ] }
```

#### `POST /api/v1/collections`
```json
{ "name": "Backend", "slug": "backend", "description": "Server-side notes" }
```
- `201 Created` (`slug` auto-derived from `name` if omitted) · `409` on duplicate slug.

#### `GET /api/v1/collections/{id_or_slug}` → `200` Collection · `404`.
#### `PATCH /api/v1/collections/{id}` → rename/describe (slug change allowed if unique) · `200`/`409`.
#### `DELETE /api/v1/collections/{id}`
Deletes the collection; entries are **not** deleted (join rows cascade). `204`.

#### `POST /api/v1/collections/{id}/entries`
```json
{ "entry_ids": ["…", "…"] }
```
Assign entries to the collection (idempotent). `200` with `{ "assigned": 2 }`.

#### `DELETE /api/v1/collections/{id}/entries`
```json
{ "entry_ids": ["…"] }
```
Unassign. `200` with `{ "removed": 1 }`.

### 4.5 Search

#### `GET /api/v1/search`

**Query parameters**

| Param | Type | Default | Notes |
| ----- | ---- | ------- | ----- |
| `q` | string | required | the query; supports `websearch_to_tsquery` syntax (`"exact phrase"`, `-exclude`, `OR`) |
| `mode` | enum | `hybrid` | `fts\|trgm\|hybrid` |
| filters | — | — | all filters from `GET /entries` (`kind`, `language`, `tag`, `collection`, `is_pinned`, `is_archived`) |
| `sort` | enum | `relevance` | `relevance\|created_at\|updated_at\|title` |
| `limit`, `cursor` | — | — | as list |

**Response `200`** — same envelope as list, plus a per-item `score`:

```json
{
  "data": [
    { "id": "…", "kind": "snippet", "title": "Debounce with useEffect", "score": 0.87, "match": "ts" }
  ],
  "next_cursor": null,
  "has_more": false
}
```

`match` indicates which branch matched (`ts` = full-text, `trgm` = fuzzy, `hybrid` = combined mode). `q` shorter than 2 chars → `422 VALIDATION_ERROR`.

### 4.6 Import / Export

#### `GET /api/v1/entries/{id}/export?format=md|json`
- `format=json` → a single `Entry` object.
- `format=md` → `text/markdown` with YAML front-matter:

```markdown
---
id: 0192f3c4-1a2b-7c3d-8e9f-0a1b2c3d4e5f
kind: snippet
title: Postgres upsert with ON CONFLICT
language: sql
tags: [postgres, sql]
collections: [backend]
created_at: 2026-11-04T15:04:05Z
updated_at: 2026-11-04T15:30:00Z
---
```sql
INSERT INTO ...
```
```

#### `GET /api/v1/export?format=json|zip`
- `json` → `{ "version": 1, "exported_at": "...", "entries": [ ... ], "collections": [ ... ], "tags": [ ... ] }` (lossless).
- `zip` → `application/zip` of Markdown files (`entries/<kind>/<slug>.md`) + `manifest.json`.
- Streaming responses for large vaults.

#### `POST /api/v1/import`
Body: the JSON export document (or multipart file). Query: `?on_conflict=skip|overwrite` (default `skip`).

```json
{
  "version": 1,
  "imported": 48,
  "skipped": 4,
  "overwritten": 0,
  "errors": []
}
```

- Dedupe by entry `id`. `skip` keeps existing rows; `overwrite` replaces them.
- Import is **atomic**: a malformed document applies nothing.
- `413 PAYLOAD_TOO_LARGE` above `IMPORT_MAX_BYTES` (default 16 MB).

## 5. Pagination

Cursor/keyset pagination ([ADR-0004](../adr/0004-cursor-pagination.md)).

- Response carries `next_cursor` (opaque, base64 of `(sort_key, id)`) and `has_more`.
- The cursor is **bound to the sort order** used to produce it; changing `sort`/`order`/filters invalidates it → `422 INVALID_CURSOR`.
- Clients should treat the cursor as opaque and never construct one.
- No total count is returned by design. If a count is needed for UI, call `GET /api/v1/entries/count` (adds a cheap `COUNT(*)`; single-user scale only).

```http
GET /api/v1/entries?limit=20
→ { "data": [ …20… ], "next_cursor": "eyJ…", "has_more": true }

GET /api/v1/entries?limit=20&cursor=eyJ…
→ { "data": [ …20… ], "next_cursor": null, "has_more": false }
```

## 6. Optimistic concurrency

- Every mutable resource returns an `ETag` (a hash of `updated_at` + `id`).
- `PATCH`/`DELETE` on entries require `If-Match`; missing → `428`, stale → `409`.
- On `409`, refetch the latest representation, re-apply changes, and retry.

## 7. Versioning & deprecation

- Breaking changes go to a new path version (`/api/v2`); the previous version is supported until the next major release.
- Additive changes (new optional fields, new enum values for `kind`) may land within `v1` — clients must tolerate unknown fields and enum values.
- Deprecations are announced in `docs/02-roadmap.md` and, where feasible, via a `Deprecation`/`Sunset` response header on affected routes.

## 8. Examples gallery

**Create a command entry**
```bash
curl -s -X POST localhost:3000/api/v1/entries \
  -H 'content-type: application/json' \
  -d '{"kind":"command","title":"Find large files","body":"find . -type f -size +100M","shell":"bash","tags":["shell","disk"]}'
```

**Search with a typo**
```bash
curl -s 'localhost:3000/api/v1/search?q=useEfect&kind=snippet&limit=5'
```

**Pin an entry (optimistic concurrency)**
```bash
ETAG=$(curl -sI localhost:3000/api/v1/entries/$ID | awk -F'"' '/ETag/{print $2}')
curl -s -X PATCH localhost:3000/api/v1/entries/$ID \
  -H "if-match: \"$ETAG\"" -H 'content-type: application/json' \
  -d '{"is_pinned":true}'
```

**Export the whole vault**
```bash
curl -s 'localhost:3000/api/v1/export?format=json' -o devvault-backup.json
```

## 9. Status code summary

| Code | Meaning | Typical routes |
| ---- | ------- | -------------- |
| 200 | OK | GET, PATCH, restore, tag/collection mutations |
| 201 | Created | POST entries/collections |
| 204 | No Content | DELETE, purge, delete tag/collection |
| 404 | Not Found | id/slug missing |
| 409 | Conflict | stale ETag, duplicate slug/tag |
| 413 | Payload Too Large | import |
| 422 | Unprocessable Entity | validation, bad cursor/format |
| 428 | Precondition Required | PATCH without `If-Match` |
| 500 | Internal Error | unexpected (see `X-Request-Id`) |
| 503 | Service Unavailable | `/ready` when DB down |
